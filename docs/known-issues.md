# 已知問題

開發過程中順帶發現、還沒修的既有問題。2026-11-07 在 main 上逐條確認過還存在。

- 除非另外註明，都是讀程式推得，沒有在遊戲裡實測。
- 程式位置只寫檔案和函式名，不寫行號（行號會漂）。
- 修掉一條就從這裡刪掉，並在 CHANGELOG 記一筆。

分類：

- **便宜可修**：修法明確、改動小。
- **要玩法決定**：要先決定玩法要怎樣，才知道怎麼改。
- **排進下一批**：已排進接下來「玩家在車上」那批修正（警察、直升機看不看得到、打不打得到車裡的人），要和那邊一起改。
- **畫面**／**開發者**：不影響玩法，或只影響開發與維護。

| 警察站得比玩家高一點（例如 0.15 m 的台階）時，按 Space 會把警察當成牆爬上去 | 步警和路障警察沒掛 `CollisionGroups`，攀爬偵測只排除角色群組和屍體群組 | 便宜可修 |
| 舉手投降沒有任何動作 | `surrender_visual_system` 只是佔位 | 畫面 |

## 戰鬥

| 玩家會遇到什麼 | 原因 | 分類 |
|---|---|---|
| 擊退推開的距離跟幀率有關：同一擊（40 傷害）在 60 fps 約推 1.4 m，在 144 fps 只推約 0.64 m。只影響 40 以上傷害或爆頭的「擊退」；25～39 傷害的「踉蹌」是固定速度與時間，幾乎不受影響 | 擊退速度每一幀乘 0.92，是按幀衰減，不是按時間（測試場景量過） | 便宜可修 |
| 敵人、行人被擊退時會被推穿牆 | 敵人、行人的擊退直接改 Transform，不經碰撞檢查（測試場景量過：每幀 0.05 秒時，牆在 0.9 m，敵人被推到 2.8 m；照公式算，60 fps 約推 1.4～1.5 m，同樣不受牆阻擋）。另一種做法是讓所有角色都走角色控制器的擊退，同時能拿掉 `hit_reaction_knockback_system` 排除敵人、行人的條件 | 便宜可修 |

## 開車、上下車

| 玩家會遇到什麼 | 原因 | 分類 |
|---|---|---|
| 被一擊打到 0 血的車不會爆炸、不會消失，殘骸一直留在路上（警車離遠了會被清掉） | 受傷（子彈、碰撞、爆炸）直接把血打到 0 時，不管原本剩多少血、有沒有在燒，都直接變成 Destroyed；`vehicle_fire_system` 不處理 Destroyed 的車 | 便宜可修 |
| 車剩很少血時，一著火幾乎馬上爆炸，不是固定燒 5 秒 | `tick_fire` 著火時每秒扣 20 血，血量歸零也算爆炸，燒的時間是「5 秒」和「剩餘血量 ÷ 20」取小的。曾實測剩 1 血時玩家比車先死，原因未查 | 要玩法決定 |

| 開車中讀取步行時的存檔，玩家會一直隱形 | 讀檔只切換「是否在車上」，不處理顯示和物理模式；玩家的顯示只有上下車轉場會改 | 便宜可修 |
| 走向車門途中按方向鍵，轉向會跟上車動畫互搶 | `player_movement` 只在「已在車上」時停止，走向車門的階段照樣寫位移和轉向 | 便宜可修 |
| 下車時面向按 F 那一刻的車頭方向，往側邊下車看起來像橫著滑出去 | 下車動畫不寫轉向；開車時跟車系統每幀把玩家轉向車頭方向 | 畫面 |
| 開車靠近任務觸發點時仍顯示「按 F」互動提示，但按 F 會直接下車；F 同時也會開關駕駛座車門 | 互動提示不看是否在車上；F 鍵先被下車處理掉 | 便宜可修 |
| 開車時，2.5 m 內有掩體點的話按 C 會進掩體，並改寫玩家位置 | 掩體輸入不看是否在車上 | 便宜可修 |

## 攀爬

| 玩家會遇到什麼 | 原因 | 分類 |
|---|---|---|
| 1.5 m 以下的矮牆、欄杆按 Space 爬不上去 | 偵測射線從胸口（身體中心上方 0.8 m，約離地 1.5 m）往前打，比這矮的東西偵測不到。`MIN_VAULT_HEIGHT` 0.3 原本「最低可翻高度」的用意因此用不到（測到的高度至少 0.8），目前它只負責擋掉「牆太高、沒找到邊緣」時的 0，不能直接刪 | 要玩法決定（降低射線會讓掩體牆、路障、車頂都能翻） |
| 用手機、對話、過場、賭場時按 Space，面前剛好有障礙物會同時攀爬 | 攀爬只看 Space 有沒有按下，沒擋這些狀態 | 便宜可修 |
| 攀爬途中按 F 會上車，攀爬動畫和上車動畫同時改位置 | 上車不看攀爬狀態 | 便宜可修 |
| 翻越時落點可能卡進別的東西裡 | 找落點的射線起點如果在別的碰撞體裡面，會在距離 0 命中 | 便宜可修 |
